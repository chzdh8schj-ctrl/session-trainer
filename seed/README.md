# seed — демонстрационные данные

1. Импорт: `powershell -NoProfile -File seed/import.ps1 -Password "<пароль>"` (backend на `http://127.0.0.1:8010`; флаг `-Replace` сначала очищает базу, без него данные добавляются).
2. Проверка файла: `node seed/validate.mjs` — структура, варианты, `correct_index`, конспекты; код выхода 1 при ошибке.
3. Содержание вымышленное и учебное: 2 предмета, 5 билетов, 10 частей («Финансы, денежное обращение и кредит», «Экономика организации») — демо для показа интерфейса, а не настоящие билеты сессии.
4. Удалять безопасно: предметы стираются кнопкой «Удалить» в интерфейсе либо повторным импортом с `-Replace` — других данных эти файлы не касаются.
5. `demo-data.json` — только источник для импорта, изменения в базе его не трогают, поэтому повторный импорт всегда возвращает демо-набор.

## Кодировка (важно для PowerShell 5.1)

- Скрипт читает файл строго как UTF-8, собирает тело `/api/import` склейкой (массив `subjects` берётся из файла как есть) и отправляет **байты** UTF-8, а не строку. Ответы `GET /api/subjects` декодируются вручную, потому что PS 5.1 считает JSON без charset за ISO-8859-1.
- После импорта скрипт сам проверяет `GET /api/subjects`: названия должны содержать кириллицу и не содержать пар `Р¤`, `Рµ`, `Рё`, `Рѕ`, `Р°` и подобных (признак «UTF-8 прочитан как cp1251»). Проверка не прошла — печатается `ОШИБКА КОДИРОВКИ` и код выхода 1.
- Такой же контроль стоит **до** отправки: если файл уже двояко закодирован, импорт не выполняется и база не меняется.
- Если на машине есть PowerShell 7, надёжнее запускать через него: `pwsh -File seed/import.ps1 -Password "<пароль>"`. Если порча всё же попала в базу (старый запуск), повторите импорт с `-Replace` — испорченные предметы заменятся.
