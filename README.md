# Тренажёр к сессии

Веб-тренажёр по билетам: предметы → билеты → части с вариантами ответов. Вход по паролю.
ИИ (DeepSeek) сам делит длинный вопрос на части и пишет варианты с мини-конспектом; всё потом правится руками.
Старт — пустой список, предметы и билеты добавляются через интерфейс и сохраняются в SQLite.

Стек: FastAPI + SQLite (порт 8010), React + Vite (dev-порт 5173).

## Что нужно поставить

- `uv` (Python) — https://astral.sh/uv
- Node.js LTS (для сборки фронта; для работы собранной версии не нужен)

## Запуск на локалке

1. Настройки: скопировать `backend\.env.example` в `backend\.env` и заполнить
   ```powershell
   cd backend
   Copy-Item .env.example .env
   ```
   - `SITE_PASSWORD_HASH` — пароль на сайт (как сгенерировать — ниже)
   - `SESSION_SECRET` — любая случайная строка: `uv run python -c "import secrets; print(secrets.token_hex(32))"`
   - `DEEPSEEK_API_KEY` — ключ DeepSeek; пусто = ИИ выключен, варианты заполняются вручную

2. Запуск (два окна: backend + фронт с горячей перезагрузкой)
   ```powershell
   cd C:\Users\remne\session-trainer
   .\deploy\start-all.ps1
   ```
   Если Windows блокирует скрипт: `powershell -ExecutionPolicy Bypass -File .\deploy\start-all.ps1`

3. Открыть http://127.0.0.1:5173

Остановить: `.\deploy\stop.ps1`

### Одним портом (как будет на сервере)

```powershell
.\deploy\build-frontend.ps1    # -> frontend\dist
.\deploy\start-backend.ps1     # -> http://127.0.0.1:8010
```

Backend подхватывает `frontend\dist` при старте, поэтому после пересборки фронта его надо перезапустить.

## Пароль

Пароль хранится **хешем** (scrypt), открытым текстом в конфиге не лежит.

```powershell
cd backend
uv run python -m app.passwords "новый пароль"
```

Полученную строку `scrypt$16384$8$1$...` целиком вставить в `backend\.env` как `SITE_PASSWORD_HASH` и перезапустить backend.
Каждый запуск даёт новую соль — подходит любой хеш от того же пароля.
`SITE_PASSWORD` (открытым текстом) оставлен как запасной вариант: работает, если хеш пуст, но при старте пишет предупреждение.

Защита от перебора: 10 неудачных попыток с одного IP за 10 минут → `429` и пауза.
Смена `SESSION_SECRET` разлогинивает всех (это нормально).

## ИИ и деньги

- Вызов идёт при добавлении билета и по кнопке «Сгенерировать заново».
- Одна генерация ≈ 0.05–0.1 ₽. Лимит по умолчанию — **500 ₽ в месяц**, правится на экране `/admin`.
- Расход считается по токенам: цены `PRICE_IN_USD`, `PRICE_OUT_USD`, курс `USD_RUB` — в `backend\.env`.
- Лимит исчерпан, ключ пуст или ИИ выключен тумблером — билет сохраняется с пустой частью, её заполняют вручную.
- Ответы кэшируются в базе: повторная генерация того же вопроса денег не стоит.

## Демо-данные

Два предмета с реальными билетами (финансы, экономика организации) — чтобы посмотреть интерфейс:

```powershell
.\seed\import.ps1 -Password "пароль"
node seed\validate.mjs      # проверка файла демо-данных
```

Демо-предметы удаляются в интерфейсе как обычные. Чистая база: остановить backend и удалить `backend\data\app.db`.

## Проверки

```powershell
cd backend; uv run pytest -q                        # 101 тест
cd frontend; npx tsc --noEmit; npm run build        # типы + сборка
node e2e\api-smoke.mjs                              # живой смоук по API (нужен запущенный backend)
node e2e\ui-check.mjs                               # отдаётся ли фронт
```

`e2e\api-smoke.mjs` берёт пароль из `$env:SITE_PASSWORD` или `--password`.
Playwright-тест в `e2e\playwright\` необязательный: нужен `npx playwright install chromium`.

```powershell
.\deploy\backup.ps1
```

Даёт `backups\app-ГГГГММДД-ЧЧММСС.db` (через SQLite backup, сервер останавливать не нужно).
Плюс сайт → `/admin` → Экспорт — JSON со всеми предметами, билетами и частями; его удобно хранить отдельно от машины.

## Как пользоваться

1. «+ Добавить предмет» — например, «Базы данных».
2. Внутри предмета «+ Добавить билет»: название и полный текст вопроса. Если ИИ включён, через несколько секунд появятся части с вариантами.
3. «Решать» — по порядку или в случайном порядке; при ошибке вылезает мини-конспект, верный вариант подсвечивается зелёным.
4. «Изменить» — правка вопроса, частей, вариантов и конспектов.

## Перенос на сервер

Пошагово: `deploy\server\DEPLOY.md`, шаблоны `session-trainer.service` (systemd) и `nginx.conf`.
Заменить плейсхолдеры `CHANGE_ME_USER` и `CHANGE_ME_DOMAIN`, в `.env` на сервере поставить `COOKIE_SECURE=true`.
